# 06. Разрыв: что есть и чего нет

Сверка спецификации (части 01–05) с кодом на момент `0.1.0-alpha.12`. Это рабочий список: при закрытии пункта его
переносят в changelog и вычёркивают здесь.

## Что сделано и проверено

| Область | Факт |
|---|---|
| Мультитенантность | организации, участники, приглашения, API-ключи, RBAC, RLS, аудит |
| Коннекторы | AWS (Cost Explorer, FOCUS-экспорт, rightsizing), GCP (BigQuery), Electricity Maps |
| Качество стоимости | защита от обрезки пагинации, лимиты чтения экспорта, привязка бакета к аккаунту, сверка с облаком, самовосстановление курсора, уведомление |
| Расчёты | usage- и cost-based углерод, SCI, версионированная методика с оговорками |
| Рекомендации и автоматизация | region shift, rightsizing, утверждение человеком, планы без исполнения, измерение результата после применения (`verified`) |
| Платформа | уведомления (e-mail, webhook, Slack), консоль оператора, журнал ошибок, движок настроек |
| Версионирование | `VERSION`, `VERSIONS.md`, `CHANGELOG.md`, `/version`, метка образов, тест согласованности |
| Клиентское меню | все 12 пунктов, страницы без бэкенда помечены |

## Очередь работ (по приоритету)

### P1. Доверие к данным
1. ~~Пересчёт с новой версией методики и сравнение версий~~ — сделано (ADR-0026). Осталось: второй, цитируемый набор коэффициентов (нужен внешний датасет), market-based расчёт, embodied.
2. ~~`verified` статус рекомендации и запись подтверждённой экономии~~ — сделано (ADR-0025); контрольная группа и сезонность — позже.
3. ~~Сверка качества для GCP и FOCUS-экспорта~~ — GCP сделано (ADR-0024); FOCUS-экспорт намеренно без внешней сверки (он сам источник истины по счёту).
4. ~~Политика хранения, экспорт и удаление данных организации~~ — сделано (ADR-0027). Осталось: документированные RPO/RTO, проверка восстановления, срок жизни резервных копий.

### P2. Продуктовые страницы
5. Страница подключённого аккаунта: ✅ состояние, сверка качества, история синхронизаций, действия (alpha.6). Осталось: права и сопоставление с проектами.
6. Carbon & Energy: интенсивность по регионам во времени, калькулятор SCI.
7. ~~Alerts: статусы new/acknowledged/muted/resolved, дедупликация~~ — сделано (ADR-0028: бюджеты и подключения). Углеродный лимит и уровень предупреждения настраиваются (alpha.8). Осталось: пороги по проектам, частота повторов.
8. Projects: окружения, команды, правила распределения общих затрат, бюджеты на проект.
9. Automation: страница поверх существующего API планов (создание, утверждение, результат).

### P3. SaaS-контур
10. Модуль `licensing` (ADR-0022): планы, подписки, лимиты, экран оператора.
11. Оператор: страница организации, очереди и повторы, временный аудируемый доступ поддержки.
12. Роли и права: редактируемая матрица, SSO-настройки через Auth0.
13. Расписания отчётов, доставка по e-mail, приглашения по e-mail.

### P4. Фазы 2–3 (из ROADMAP)
14. Kubernetes (Kepler → Prometheus → agent), Azure, WattTime.
15. Импорт публикуемого набора коэффициентов, embodied emissions.
16. GitHub Actions / GitLab, carbon-aware планирование, исполнители с dry-run.

### Ключи внешних сервисов в консоли (сделано в alpha.10, ADR-0029)
Electricity Maps и SMTP управляются из консоли оператора. Остаётся перенести туда то, что сейчас читается при старте и
требует перезапуска: Sentry, OTLP, S3, платформенные аккаунты AWS/GCP. Правило для новых интеграций записано в `CLAUDE.md`.

## Сознательные отказы

Отложены до измеренной необходимости: шина событий, Temporal, Vault, выделение микросервисов, отдельная
аналитическая БД. Основание и триггеры пересмотра — в [части 05](05-stack-and-external-services.md) и ADR-0005.

## Чек-лист перед релизом beta

Критерии перехода alpha → beta описаны в [`docs/release/versioning.md`](../release/versioning.md). Дополнительно
для этого списка: пункты P1 закрыты; тест изоляции тенантов покрывает API, экспорты, фоновые задачи; у каждого
экрана клиента есть источник данных и пустое состояние; у каждого действия оператора есть право и аудит.
