## Известные ограничения расчётов (аудит alpha.24)

- Валюты: итоги приводятся к одной валюте отчёта по курсам ЕЦБ за день (alpha.51–52); сумма в валюте без курса не входит в итог, и KPI говорит, какая валюта и сколько сумм. Курсы справочные, не расчётные.
- Интенсивность без показаний за день берётся из последнего показания (не старше допустимого) или из последнего
  известного; с alpha.26 строка помечена источником и основанием (ADR-0035). Строки, рассчитанные раньше, без пометки.
- Расчёт «по стоимости» при наличии измеренного использования того же сервиса, региона и дня отбрасывается целиком
  (иначе энергия удвоилась бы), поэтому часть затрат сервиса может не попасть в углерод.
- Расходы на платные API считаются в запросах, а не в деньгах (цена запроса зависит от тарифа провайдера); суточный лимит есть только у провайдера интенсивности сети.
- ~~Прогноз бюджета линейный~~ — сделано (alpha.155, ADR-0053): рисунок по дням недели, тренд, диапазон 80%, учёт неполных последних дней. Остаётся: сезонность по месяцам года (нужно больше истории, чем есть у клиентов в начале).

## Найдено при проверке alpha.108–112 (QA-проход)

- ~~Стоимость рекомендации переноса только для AWS EC2~~ — сделано (alpha.99–144): индексы цен AWS, Azure, GCP и управляемых сервисов (RDS, ElastiCache, PostgreSQL и Redis Azure, Cloud SQL, Memorystore). Остаётся «not estimated» для сервисов вне корзин.
- Задержка между регионами (ADR-0046, alpha.119): замеры Microsoft (Azure) и CloudPing (AWS) где они опубликованы, иначе оценка по прямой,
  подогнанной под 3200 замеренных пар (6 мс + 0,0156 мс/км, погрешность ±24% для 80% пар); источник виден у каждой цифры. Остаётся: для GCP и
  между облаками замеров нет (только оценка), это задержка «регион → регион», а не от пользователей клиента, и нет ограничения по типу
  нагрузки (интерактивная / пакетная) на проект, а не только на организацию.
- Electricity Maps на текущем ключе не отдаёт историю (401): весь период до подключения оценивается по последнему показанию (96% строк на стенде).
- Частично закрыто в alpha.116: бесплатные источники IESO (Онтарио, история 90 дней загружена) и Hydro-Québec (Квебек: открытая история кончается 2026-01-02, дальше только живая лента за 2 суток, накопление с подключения). Остальные регионы вне США/Европы/GB/Канады по-прежнему на одном источнике.
  Для Канады нет бесплатного источника с историей; Ember для Канады отстаёт на месяцы. Это видно клиенту («0% measured») и оператору (Aggregation → Provenance).
- Добавлены в alpha.121: ENTSO-E (Европа, нужен бесплатный токен: вводится в консоли оператора, Integrations → ENTSO-E; все 32 кода зон сверены с публичным списком ENTSO-E (entsoe-py), живого токена ещё не было) и ONS
  (Бразилия, без ключа, проверен живыми данными). Остаётся без бесплатного источника с историей: Япония, Индия, Сингапур, Корея, Австралия (OpenElectricity
  под CC BY-NC не подходит, AEMO NEMWEB требует реестра DUID).
- Почасовое обновление интенсивности идёт по всем 126 регионам каталога при суточном лимите 2000 запросов: регионы клиентов обновляются первыми, остальные ждут.

## Разнесение расходов по тегам (alpha.169)

Сделано (ADR-0061): showback по тегам облака для Azure, AWS (выгрузка FOCUS) и GCP (labels); проверено вживую на Azure, AWS и GCP только на заглушках. Остаётся: углерод по тегам,
слияние написаний (env/environment), теги AWS через Cost Explorer, догрузка тегов глубже окон синхронизации.

## Затраты на SaaS (alpha.170)

Сделано (ADR-0062): загрузка CSV-выгрузки затрат любого поставщика вне трёх облаков (Datadog, Snowflake и т. п.), с тегами; без углерода. Остаётся: прямые коннекторы к API поставщиков,
регулярная загрузка по расписанию (сегодня файл присылает человек или его скрипт с ключом API), XLSX и JSON.

## Обязательства и предел расходов (alpha.152–153)

- Предел по объёму расходов `limits.tracked_spend` работает (ADR-0050): предупреждение выше 100%, отказ в новом подключении выше 120%.
- Отчёт по обязательствам (ADR-0051) показывает ровную часть расходов, экономию и риск; скидки ориентировочные, вводятся вручную.
  alpha.157 (ADR-0054): чтение уже купленных обязательств и их использования у AWS, совет «докупить / не трогать / сначала исправить»,
  экономия подтверждается относительно остального проекта. Остаётся: чтение у Azure и GCP, рекомендация покупки по семействам и регионам, сама покупка.

## Автоматизация данных о сети (alpha.34)

Ежедневное задание само подгружает прошлое региона и пересчитывает проекты, если у региона пробелы; бесплатные источники
(UK Carbon Intensity, Ember) подключаются без ручных шагов. Осталось: маржинальная интенсивность (WattTime) вместе с carbon-aware планированием по
предельным выбросам: клиент готов (ADR-0049), ENTSO-E и EIA подключены с alpha.121.

### Ключи внешних сервисов в консоли (сделано в alpha.10, ADR-0029)
Electricity Maps и SMTP управляются из консоли оператора. Всё, что читается при старте (Sentry, OTLP, S3, платформенные аккаунты AWS/GCP), тоже задаётся в консоли и применяется
после перезапуска (alpha.15). Правило для новых интеграций записано в `CLAUDE.md`.

## Сознательные отказы

Отложены до измеренной необходимости: шина событий, Temporal, Vault, выделение микросервисов, отдельная
аналитическая БД. Основание и триггеры пересмотра — в [части 05](05-stack-and-external-services.md) и ADR-0005.

## Чек-лист перед релизом beta

Критерии перехода alpha → beta описаны в [`docs/release/versioning.md`](../release/versioning.md). Дополнительно
