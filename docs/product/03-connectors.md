# 03. Коннекторы

Каталог интеграций, жизненный цикл подключения и контракт, которому следует каждый коннектор. Цель контракта:
новый провайдер подключается без переписывания клиентской админки и остальных доменов (ADR-0008).

## Каталог

| Google Cloud | cloud | ✅ | `connector/gcp` | экспорт биллинга в BigQuery, измеренные compute и storage |
| Microsoft Azure | cloud | 🗓️ фаза 2 | — | Cost Management API |

## Жизненный цикл подключения

```
create (ExternalId выдан) → configure access → verify → select sources/projects → first sync → healthy
                                                  │                                      │
                                                  └── error (access denied, не ретраится) ┘ → reconnect
```

1. **Выбор интеграции** из каталога.
2. **Настройка доступа:** AWS — роль `ReliabilixReadOnly` с ExternalId на подключение; GCP — сервисный аккаунт и
   проверка владения экспортом. Платформа не хранит долгоживущих ключей (ADR-0010).
3. **Проверка (`verify`):** учётные данные, права, доступность источника, принадлежность источника этому аккаунту.
4. **Выбор данных и проекта:** какой источник (Cost Explorer или экспорт), к какому проекту привязано.
5. **Первая синхронизация и контроль полноты:** сверка с суммой облака (см. часть 04, «Качество данных»).

Состояния подключения: `pending`, `healthy`, `error`. «Access denied» переводит в `error` и не ретраится;
временные ошибки ретраятся очередью.

## Контракт коннектора

Интерфейс `CloudProvider` (`Validate`, `GetUsage`) плюс нормализатор в `ingestion`, который приводит ответ к
FOCUS v1.4. Требования к реализации:

| Требование | Зачем |
|---|---|
| Только чтение, минимальные права | клиент даёт минимум |
| Пагинация без молчаливой обрезки: превышение лимита — ошибка | иначе тихая потеря данных |
| Ограничения на размер, глубину, длину строки при чтении экспортов | защита от аномальных файлов |
| Привязка источника к аккаунту клиента (`ExpectedBucketOwner`, доказательство владения) | защита от подмены источника |
| Идемпотентный импорт: повтор не удваивает стоимость | ретраи безопасны |
| Контрольные суммы для сверки с облаком | проверка качества |
| Отсутствующая стоимость ≠ 0 | честность данных |
| Свой номер версии в `VERSIONS.md` | видно, какая реализация работала |

## Порядок волн (скорректирован)

Исходный набросок предлагал первой волной AWS, Kubernetes, GitHub Actions, Prometheus. По факту:

1. ✅ AWS и GCP (биллинг, сверка качества, рекомендации).
2. Kubernetes (Kepler → Prometheus → agent) и Azure.
3. GitHub Actions / GitLab CI, исполнители Terraform/Kubernetes за отдельными правами.

Kubernetes раньше CI/CD, потому что данные об энергии контейнеров дают больше точности расчёта, чем оценка сборок.

## Что должна показывать страница подключённого коннектора

Overview · Connection & permissions · Data sources · Sync history · Data coverage / качество (сверка с облаком,
пропущенные дни, свежесть) · Project mapping · Security (последняя проверка, ротация) · Actions
(Sync now, Test connection, Reconnect, Disconnect). Сейчас доступны статус, история синков, ручной sync и экспорт;
остальное — в [очереди работ](06-gap-analysis.md).
