# 01. Клиентское рабочее пространство

Рабочая панель клиента: анализ расходов и углеродного следа, подключения, рекомендации, отчёты. Эталон дизайна —
макет Reliabilix GreenOps Analytics Dashboard: тёмный левый sidebar, светлая область с белыми карточками, сине-зелёные
акценты, фильтры проекта и периода сверху. Все страницы — части одного продукта: один sidebar, одна система компонентов,
одна логика навигации.

Статусы: ✅ работает на реальных данных · 🟡 частично · 🗓️ заглушка (страница есть, бэкенда нет).

## Пустое состояние

До первых данных страницы показывают честное пустое состояние и следующий шаг, а не фиктивные значения:
KPI — «—», рекомендации — «недоступны до первого расчёта». Онбординг: организация → подключение облака →
первая синхронизация → проекты и функциональная единица → первый расчёт.

## Роли клиента

Фактические роли в коде (`platform/auth`): `owner`, `admin`, `engineer`, `viewer`, `billing`. Сервер проверяет
право на каждый запрос. Пользовательские роли и матрица прав редактируются позже (см. ROADMAP).

| Роль | Может |
|---|---|
| owner | всё: чтение, управление подключениями/участниками/настройками, утверждение рекомендаций и планов автоматизации |
| admin | чтение, управление участниками, подключениями, проектами, настройками; видит планы автоматизации, но **не утверждает** изменения инфраструктуры |
| engineer | чтение, расчёты, отчёты, CI-gate; применяет рекомендации, создаёт и утверждает планы автоматизации; читает настройки и получателей уведомлений |
| billing | стоимость, углерод, бюджеты, отчёты |
| viewer | только чтение дашбордов и отчётов |
| ci | только API-ключ CI: `ci:evaluate` |

## Подробности по страницам, чего ещё нет

- **Projects.** Нужно: окружения (prod/staging/dev), владельцы и команды, правила распределения общих затрат
  (аккаунт может обслуживать несколько проектов — стоимость не копируется в каждый, а распределяется по правилам),
  бюджеты на проект.
- **Cloud Accounts.** Нужно: страница аккаунта с вкладками Overview / Billing / Permissions / Sync history / Project
  mapping / Security. Полнота данных и сверка с облаком (см. часть 04) уже считаются на бэкенде и выводятся в статусе.
- **Carbon & Energy.** Нужно: регионы и интенсивность по времени, калькулятор SCI (приложение, период, функциональная
  единица, входные данные и ограничения), сравнение периодов.
- **Recommendations.** Нужно: страница рекомендации (доказательства, текущая и предлагаемая конфигурация, риски),
  отдельный статус «verified» с подтверждённой экономией после сравнимого периода, snooze и тикет.
- **Reports.** Нужно: расписания, доставка по e-mail, сравнение периодов, версия методики и время формирования
  в каждом отчёте (версия методики уже сохраняется).
- **Alerts.** Нужно: правила и пороги (бюджет, аномалия, углеродный порог), статусы new/acknowledged/resolved/muted,
  подавление дублей и частота повторов.
- **Settings.** Нужно: роли и права, SSO/MFA (через Auth0), API и webhooks с журналом использования, экспорт и
  удаление данных, тариф и биллинг (ADR-0022).
